# 手の撮影(Web アプリ)

カメラの映像から、手の点(21個)を見つけて、**手のひら・手の甲(右手・左手)**を、ガイドに合わせて、撮る Web アプリです。条件(手の向き、指が重なっていないか、近さ、明るさ、止まっているか、ピント)が、そろって、約1秒、保たれると、自動で撮ります(手動の「撮影」ボタンも、あります)。

- 映像と写真は、**この端末の中だけ**で、処理します。サーバーには、送りません。
- 撮影を助ける、ガイドです。**医療の判定では、ありません**。
- 手の検出に、Google の MediaPipe(Apache License 2.0)を、使っています。

## 公開(2026-11-22)

- 公開アドレス: **https://quiet-ridge-7.github.io/hand-photo-web/** (GitHub Pages。https なので、iPhone でも、カメラが使えます)。検索には、出にくくしてあります(`noindex`)。
- 映像と写真は、**見る人の端末の中だけ**で、処理します。サーバーには、送りません。GitHub Pages には、ページを開いた記録(アクセス記録)が、残ることがあります。
- 確かめた: ブラウザ(Edge)で、公開のページが開き、手のモデルが読み込めて、サービスワーカーが動くこと。**本物の手で(この PC)**: 左手・右手の判定が、逆に出ないこと、爪の四角と、切り出しの位置(2026-11-22。作者が、確認しました)。**確かめていない**: iPhone の実機。

## 動かし方(この PC で)

`run.bat` を、ダブルクリックします(Python が、必要です)。ブラウザが、開きます(`http://localhost:8784/`)。カメラの使用を、許可してください。止める時は、黒い窓で、Ctrl+C を、押します。
(`run.bat` は、`serve.py` を使います。ブラウザに、ファイルを、とっておかせない設定で、新旧のファイルが、混ざらないようにしています。画面の右の列の「版: app … / guide …」が、同じ値なら、新しいファイルです。違うときは、Ctrl+F5 を、押してください。)

## 撮り方

1. 初めは、「手のひら・手の甲(右・左)」です。**左手のひら → 左手の甲 → 右手のひら → 右手の甲**の順に、4つ、撮ります。映像の**上**に、4つが、横一列で、出ます(左から、左手のひら、左手の甲、右手のひら、右手の甲)。次に撮る物は、青い枠、撮れた物は、緑です。映像の**左上**には、いま撮っている項目が、大きく出ます(例: 「撮影中: 左手の甲」。全部、撮れたら「全部、撮れました」)。まだの物を押すと、それを、次に撮る物にできます。**まだ1枚も撮っていない時に、逆の手(例: 左手の番に、右手)が、先に映ったら、その手から始めます**(手のひらから。順番は、右手のひら → 右手の甲 → 左手のひら → 左手の甲、のように、続きます)。自分で、4つのどれかを押して、選んだ時は、手が違っても、勝手には、変えません。
2. 画面の、ガイドの文に、従って、手を動かします。条件(撮る手が、右 / 左で、合っていることも、含む)が、そろうと、枠が緑になり、約1秒で、**自動で撮れます**。撮れたら、その項目が緑になり、「撮れました: 左手のひら。次は、左手の甲です」と、案内します(約2秒の間をあけて、次へ)。画面は、止まりません。「撮影」ボタンで、いつでも、手動でも、撮れます。
3. 撮れた写真は、**この端末のメモリの中だけ**に、あります(ページを閉じると、消えます)。右の列に、撮れた物の、小さな写真と、「撮り直す」が、出ます。「保存(○枚)」で、まとめて保存します(爪の写真も、含みます): iPhone は、共有の画面(4枚を、まとめて。「画像を保存」)、PC は、ダウンロード(4つ)。「最初から、撮り直す」を、**2回**押すと、全部、消します(1回目で、ボタンが赤く『もう一度、押すと、全部、消えます』に変わり、4秒で、元に戻ります。ブラウザの確認の窓は、使いません。iPhone で、確認の窓の後に、映像が止まったため)。ファイル名は、`hand_left_palm_日付_時刻.jpg` のようになります。
4. 撮影は、鏡に映さず、**カメラの、そのままの向き**で、保存します。
5. 画面の「いま見えている手: 右手の手のひら側」で、手の左右の判定が、合っているかを、確かめられます(左手・右手とも、本物の手で、合っていることを、確かめました)。

## 手の形のガイド

- **手の形のガイド**(画面の真ん中に、うすい白い形。次に撮る物〔右手のひら など〕の形): 正面向きで、指を開いた手の形です。ここに、手を重ねます。手の左右は、最後に見えた手に合わせ、手のひら / 甲で、親指の側が変わります。いまの手との、一致した面積(重なり ÷ 合わせた面積。どちらも、手の点から作った、太らせた骨組みの形)が、50%以上になると、ガイドが緑になります(`T.guideOverlap`)。チェック一覧の項目**「ガイドに重なっている」**(「そのまま」が 50% 以上)は、**条件に入っています**(緑のバーと、自動撮影にも、効きます。2026-11-22 に、戻しました)。一致の**数字の行は、出しません**。一致の計算(`guideMatch`。「そのまま」と、位置・向き・大きさをそろえた「形だけ」)は、`guide.mjs` に、残してあります。指先のモードでは、ガイドは出ません。 **縦長の画面(スマホ)では、ガイドを、大きく**します(横長の画面〔PC〕は、手の大きさ 約 0.80、縦長は 約 0.95。`GUIDE_FILL` / `GUIDE_FILL_PORTRAIT`)。あわせて、「近さ」の上限を、0.98 から 1.10 に、上げました(縦長の画面で、ガイドの大きさの手が、「近い」と言われないように)。
- 手の向き(pan / tilt / roll)、奥行きの色、輪郭(水色の線・分割モデル)は、不要になったので、2026-11-21 に、取り除きました(履歴には、残っています)。手の点の3次元の位置(`worldLandmarks`)は、もう、使っていません。

## 自動撮影: 1秒の間に、1コマでも、ピントが合えば、OK。 いちばん、くっきりした1コマを、残す

- **ピント(くっきり度 15 以上)は、1コマごとではなく、1秒の間で、見ます**(2026-11-25)。ピント**以外**の条件が、そろっている間、時間を数え、その間に、くっきり度を、測るたび(3コマに1回。1秒で約10回)、**いちばん高い値**を、覚えます。**1秒たった時に、いちばん高い値が、15 以上なら**、撮ります。途中に、15 を下回るコマが、混ざっていても、数え直しには、なりません。
- 1秒たっても、15 に届いていなければ、そろっている間は、**待ち続け**、**1コマでも、15 を超えたら、すぐ**、撮ります。画面には、「ピントを、合わせています。そのまま、お待ちください」と出ます。
- 写真にするのは、**その間で、いちばん、くっきりした1コマ**です(撮る瞬間のコマでは、ありません)。手の甲の爪の切り出しも、**そのコマの、手の点**で、行います。撮った直後の文に、「いちばん、くっきりした1枚です(くっきり度 ○)」と出ます。
- **ピントの下限は、40 から 15 に、下げました**(2026-11-25)。40 は、最初の測り方(手の中心 160 画素・1か所)で、決めた値で、のちに、測り方が、変わった(96 画素・6か所の最大)後も、そのままでした。スマホ(解像度が高い)では、`sharp` が、20〜30 に、なるためです。
- ピント以外の条件が、1つでも、外れたら、時間も、いちばん高い値も、数え直しです。手動の「撮影」ボタンは、**いまの映像**を、撮ります。
- 「確認用の数字」に、`sharpBestIn1s`(その間の、いちばん高い、くっきり度)が、出ます。

## 「止まっている」の条件を、外しました

- チェック項目の「**止まっている**」(手の動きが、画面の対角の 1.2% 以下)を、**外しました**(2026-11-25)。条件が、そろえば、手が動いていても、撮れます(それでも、ピント以外の全条件が、**1秒続く**まで、撮りません。ピント〔くっきり度 15 以上〕は、1秒の間に、1コマでも、超えれば、OKです)。動きの数字は、「確認用の数字」の `motion` に、これまでどおり、出ます(判定には、使いません)。

## 映像の大きさ(スマホで、ときどき、映像だけが、小さく出る)

- **症状**(2026-11-25。スクリーンショットで確認): 縦持ちの iPhone で、ときどき、**映像の絵だけ**が、枠の真ん中に、小さく(期待の約 56%)出て、**ガイドや手の点は、正しい大きさ**で描かれ、ずれる。映像は、縦長(9:16)で来ていたので、『縦持ちなのに、横長の映像が来る』という、前の仮説は、原因では、ありませんでした。
- **対策**: 映像と、描画の絵(オーバーレイ)の、**大きさと位置を、こちらで、計算して、決めます**(ブラウザの自動の計算〔高さ auto と object-fit〕に、頼りません)。見た目は、これまでと、同じです(幅は、枠いっぱい。高さは、画面の 70%〔PC の 2列表示は 80%〕まで。超える時は、縦に合わせて、左右に、黒い余白)。映像と描画の絵は、**必ず、同じ大きさ・同じ位置**になります。
- **自己修復**: 6コマに 1回、期待の大きさと、実際の大きさを、比べて、ずれていたら、指定し直します。画面の向きが変わった時や、映像の大きさが変わった時も、計算し直します。
- **確かめていない**: これが、本当の原因かは、**iPhone の実機で、小さくならなくなるかを、見て、確かめる必要があります**。
- 試験(`app_smoke_test.mjs` の L): 縦持ちのスマホ(390 × 844)に、縦長(9:16)の映像を送り、期待の大きさで出ること、描画の絵と同じこと、映像の大きさを、小さく書き換えても、自分で直ること。

## カメラの始まり(iPhone で、『準備しています』のまま、止まる時)

- カメラの許可の確認の窓の答えが、**6秒たっても来ない**時は、「カメラの許可の確認が、出ていませんか?『許可』を選んでください。…」と、案内を出します(iPhone は、設定 → Safari → カメラ も、確かめる)。
- 画質の指定(1920 × 1080)が、通らない端末でも、**指定をゆるめて**(向きだけ → 何も指定しない)、やり直して、カメラを始めます。
- 映像の再生の答えを、待たずに、状態を進めます(iPhone で、答えが来ない時にも、止まらないように)。(2026-11-23。『v36 で、カメラが、準備しています、のまま』という報告を受けて、足しました。原因は、まだ、特定できていません)

## 撮れた時の「撮れました」の表示

- **撮れた時に、映像の真ん中に、「撮れました。 / 次は、左手の甲」だけを、大きく出します**(緑の枠。4つ目が撮れた時は、「4つ、全部、撮れました。」)。約3秒で、消えます。音は、ありません(2026-11-23 に、取り除きました。スマホで、聞こえなかったため)。
- **ガイドは、腕の角度に合わせて、傾きます**(2026-11-23): **左手は、右へ、右手は、左へ、40度**(`GUIDE_TILT_DEG`。画面で見た向き。手首を中心に回します)。自然に手を上げた時の、腕の向きに、近づけるためです。前面カメラ(鏡のように映す)の時も、**画面で見て**、同じ向きになります。傾けても、はみ出さないよう、必要なら、少し、小さくします。試験用に、アドレスの末尾に `?tilt=0` を付けると、傾けません(`?tilt=20` のように、角度も、指定できます)。
- ガイドの輪郭を、**なめらか**にしました(2026-11-23): 小指のところの、段差(ギザギザ)は、手のひらの辺の太さを、指の太さと、そろえ、辺の上に、円を、細かく(25個)並べて、なくしました。
- ガイドの手の形は、**小指の下の、手のひら(小指の付け根から、手首まで)を、外へ、ゆるく、丸く**しました(2026-11-23。まっすぐな斜めの線だと、本物の手に、合わせにくいため。`SIL_BULGE`。ガイドと、いまの手の、形の計算〔一致の面積〕でも、同じ形を使います)。
- ガイドの手の形(うすい白)は、**白を、少し、強く**しました(うすさ 0.22 → 0.34)。色のついた縁と、影は、スマホで画面が止まったため、取り除きました(絵を作り直す処理が、重かったため)。

## 爪(指先)の四角(手の甲を撮る時)

- 手の甲を撮る番(左手の甲・右手の甲)に、5本の指先の、爪のあたりを示す、**水色の四角**を、映像に重ねて出します(`fingertipRects`)。後で、ここを、切り出して、爪の写真にするための、範囲です。
- 四角は、**指の向きに合わせて、傾きます**。指の向き = 第1関節から、指先へ。縦 = (第1関節〜指先)の 1.875 倍(指先の先まで)、横 = 1.25 倍(`NAIL_BOX` で調整。2026-11-22 に、上と横を 1.25倍、さらに、上を 1.2倍にしました。下の辺は、第1関節のまま)。
- **手の甲を撮ると**、その瞬間の四角で、**5本の爪(指先)の写真を、切り出します**。指の向きが、真上になるように、回して、切り出します(拡大はしません。大きさは、四角の、画素の大きさです)。右の列の、撮れた手の甲の項目の下に、**小さな写真(サムネイル)5枚**が、並びます。
- サムネイルを**押すと、拡大**して表示します(「前へ」「次へ」、または、左右の矢印キーで、5本を、順に。どこかを押す、または、Esc で、閉じます)。
- 手のひらの写真からは、切り出しません。「撮り直す」「最初から、撮り直す」で、爪の写真も、消えます。写真は、この端末の、メモリの中だけです。
- **保存ボタンは、1つ**です(「**保存(○枚)**」)。手のひら・手の甲の全体の写真(最大4枚)と、爪の写真(手の甲 1つにつき 5枚)を、**まとめて**保存します(例: 4つ撮れて、手の甲が2つなら、14枚)。iPhone は、共有の画面に、まとめて渡します。PC は、ダウンロードです。ファイル名は、全体の写真が `hand_left_back_日付_時刻.jpg`、爪が `hand_left_back_nail_index_日付_時刻.jpg` のように、**指の名前**(thumb、index、middle、ring、pinky)が付きます(日付・時刻は、同じ手の甲の、全体の写真と同じ)。項目ごとの保存ボタンは、ありません(項目ごとには、「撮り直す」だけ)。

## 撮影のオン・オフ

- 4つの撮影は、いつも、**オン**です。試験などで、切りたい時は、アドレスの末尾に `?capture=0` を付けて、開きます(自動の撮影も、「撮影」ボタンも、無くなります)。
- 指先のモード(爪・指先の撮影)は、2026-11-21 に、取り除きました(履歴には、残っています)。

## PWA(ホーム画面に追加・オフライン)

- 公開用(Web)に向けて、**PWA**にしました(顔のアプリ `face-teeth-web` と同じ形): `manifest.webmanifest`(名前「手の撮影」、全画面 `standalone`、色 #0f172a)、アイコン(`icon-192.png`、`icon-512.png`。手と、緑の爪の絵)、`sw.js`(サービスワーカー)、`licenses.txt`(MediaPipe と手のモデルのライセンス表示)。
- `sw.js`: コード(`index.html`、`app.js`、`guide.mjs` など)は「**ネットを先に**」。しかも、ブラウザの覚え(GitHub Pages は、ファイルを10分、覚えさせます)を、使わず、**毎回、サーバーに、確かめます**(`cache: "no-cache"`。変わっていなければ、軽い返事だけ。2026-11-23 に、足しました。公開した変更が、スマホに、すぐ、反映されないことがあったため)(新しい物が、すぐ反映される。ネットが無い時だけ、覚えた物)。大きな物(`lib/` の MediaPipe、`models/` の手のモデル。約22MB)は「**覚えた物を先に**」(初めての時だけ、ネットで取る)。外のサイトとは、通信しません。写真や映像は、覚えません(メモリの中だけ)。
- **この PC(`localhost` / `127.0.0.1`)では、サービスワーカーを登録しません**(古い物が残って、開発の邪魔になるため。`run.bat` は、キャッシュさせない `serve.py` を使います)。試験の時だけ、アドレスの末尾に `?sw=1` を付けると、登録します。
- コードを変えて、覚えた物を入れ替えたい時は、`sw.js` の `VERSION` を上げます(公開した後に、必要です)。
- iPhone では、公開(https)した後、Safari の共有から「ホーム画面に追加」で、アプリのように、全画面で開けます(**実機では、まだ確かめていません**)。
- 試験(`app_smoke_test.mjs` の C): manifest とアイコンが読める、`?sw=1` で登録して覚える、2回目に大きな物も覚える、**ネットを切っても開ける**(オフライン)。

## 確認用の数字

画面の下の「確認用の数字」に、判定に使った数字が、出ます(手の左右、手のひらか甲か、大きさ、傾き、指の伸び・開き、明るさ、動き、ピント)。判定が、おかしい時の、手がかりに、なります。

## 確かめたこと / 確かめていないこと

- 確かめた: Windows の Edge(自動試験。偽のカメラ、人工の手の点)。本物の MediaPipe の手のモデルが、読み込めて、動くこと。**本物の手(この PC)で、右手・左手の判定と、爪の四角・切り出しの位置**(2026-11-22)。
